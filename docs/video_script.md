# 录屏答辩逐字讲稿（约 6 分钟）

各位老师好，我这次课程设计的题目是“人脸图像预处理及人脸检测系统设计”。下面我会从设计目标、系统实现、运行演示、实验结果和不足这几个方面进行介绍。

先说一下我为什么要做预处理。真实环境里的人脸图片不一定是标准证件照，可能光线很暗，也可能有噪声、背景复杂或者人脸比较小。如果直接把这些图片送入检测器，容易出现漏检。所以我的整体思路是，先把图像尺寸统一，再生成多种预处理结果，分别进行人脸和人眼检测，最后保存对比图和指标。这样既能看到结果，也能分析是哪一种处理真正起了作用。

现在看一下项目结构。主程序是 `main.py`，它只负责解析命令和组织流程，没有把所有代码堆在一个文件里。`image_io.py` 负责图片读写，而且对中文路径也可以正常处理；`preprocess.py` 负责灰度化、直方图均衡化、CLAHE、高斯滤波、中值滤波、尺寸归一化和 Gamma 校正；`detector.py` 负责加载 OpenCV 自带的 Haar 分类器并检测人脸和人眼；`evaluator.py` 统计数量、耗时和稳定性；`visualizer.py` 负责画框和拼接结果。

预处理部分一共生成七个分支，包括原图、灰度图、全局均衡化、CLAHE，以及滤波后再 CLAHE、Gamma 后再 CLAHE。这里我没有把所有操作简单串成一条很长的流水线，因为预处理并不是越多越好。比如全局均衡化能提高对比度，但在噪声比较明显时也可能把噪声一起放大。CLAHE 把图像分成小块并限制对比度增益，对局部光照不均更合适。高斯滤波对随机噪声比较有效，中值滤波对椒盐噪声比较有效。尺寸归一化使用等比例缩放再填充黑边，避免直接拉伸导致人脸变形。

检测部分使用的是 OpenCV 自带的正面人脸 Haar 分类器和带眼镜人眼分类器。Haar 方法通过矩形特征描述眼睛、鼻梁和面颊等区域的明暗差异，再利用积分图快速计算特征。AdaBoost 会从大量特征里选择区分能力较强的特征，级联结构可以先快速排除大部分背景窗口。检测到人脸后，我只在人脸上方百分之六十五的区域继续找眼睛，并且最多保留两个面积较大的候选，这样能减少嘴部和背景被误认为眼睛的情况。

下面演示运行。先在终端进入项目目录，执行 `python main.py --input data/raw/sample_lena.jpg --output results/detection`。程序会输出处理完成的信息，并告诉我表现较好的预处理分支、人脸数量、人眼数量和耗时。再执行 `python main.py --batch data/raw --output results/detection --optimize`，就可以批量处理文件夹里的图片，并进行一组小规模参数搜索。

现在打开 `results` 文件夹。`detection` 目录保存每个预处理分支的检测结果，绿色矩形是人脸，红色矩形是人眼。`comparison` 目录把多个结果拼成一张图，方便观察原图、均衡化、滤波和 Gamma 校正的差别。`metrics` 目录同时生成 CSV 和 JSON。CSV 可以直接用 Excel 打开，JSON 里还记录了稳定性和参数搜索过程。

参数优化主要考虑三个参数。第一个是 `scaleFactor`，它越接近 1，尺度搜索越细，可能找到更小的人脸，但耗时也会增加。第二个是 `minNeighbors`，数值高可以减少误检，但也可能漏掉不明显的人脸。第三个是 `minSize`，用来过滤太小的候选区域。因为当前演示数据没有人工标注框，我没有把检测数量直接说成准确率，而是用不同预处理分支的非零检测比例、数量一致性、人眼证据和耗时组成一个代理分数。这个分数适合做初步筛选，最后仍然要结合对比图人工检查。

实验中比较明显的问题有两个。第一个是弱光图像直接检测容易失败，Gamma 加 CLAHE 通常能让暗部特征更清楚。第二个是大角度侧脸。当前使用的是正面人脸分类器，所以它对轻度偏转可能还能检测，但对大角度侧脸能力有限。参数调整只能改善一部分情况，不能突破分类器本身的训练范围。后续可以增加侧脸 Haar 分类器，或者换成基于深度学习的人脸检测器。另一个改进方向是给测试图人工标注人脸框，然后计算准确率、召回率和 IoU，这样评价会更客观。

最后总结一下，这次课程设计完成了图像预处理、人脸和人眼检测、参数配置与搜索、批处理、对比图生成以及 CSV 和 JSON 指标导出。通过这个项目我最大的体会是，图像预处理需要针对具体退化类型选择，检测参数也要在速度、误检和漏检之间做平衡。我的介绍到这里，谢谢老师。
